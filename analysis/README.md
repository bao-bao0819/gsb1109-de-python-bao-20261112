# LRU vs LFU 回源可达范围分析

数据平台只抽样到部分分区访问记录。本工具在不臆造缺失请求的前提下，
枚举与抽样日志一致的所有**补全序列**，精确计算 LRU 与 LFU 回源
（缓存未命中）次数之差的可达范围，并给出见证上下界的具体回放。

## 数据模型

- 观测到的请求按原顺序保留。
- 每个缺失段用 `Gap(length, allowed)` 描述：缺失 `length` 个请求，
  每个请求只能取 `allowed` 分区集合中的键（允许重复）。
- 补全序列 = 用允许的键填满所有缺失段后得到的具体请求序列。
- 两个策略始终从**同一个空缓存**开始，容量相同。

差值定义在单条补全序列上：

```
d = LRU 回源次数 - LFU 回源次数
```

`d > 0` 表示 LFU 更省回源，`d < 0` 表示 LRU 更省回源。

## 方法

1. `policies.py` 内置与 `cachetools.LRUCache` / `cachetools.LFUCache`
   一致的轻量仿真（LFU 同计数按最久未用淘汰），逐请求统计回源，
   并支持状态快照/恢复。测试逐请求比对真实缓存类，保证语义一致。
2. `reach.py` 用动态规划求精确可达范围：
   - 联合状态 = `(LRU 快照, LFU 快照)`；
   - 每个联合状态只保留到达它的最小、最大 `d` 及对应补全见证；
   - 观测请求只有一种走法；缺失段在其长度与允许集合上再做一层 DP；
   - 最终在所有终止状态中取全局最小/最大，并各自重放校验回源计数。
3. `bruteforce.py` 枚举全部补全序列，作为小样本上的独立参照实现，
   随机 fuzz 与 DP 结果逐项一致。

## 上下界来自同一条补全序列

每个界面对应一条具体补全序列，LRU 与 LFU 的回源数都在**这同一条
序列**上各自重放得到，再相减。因此不会出现“两个策略各挑一条对自己
有利的序列”的不公平比较。两个界面对应的序列可以不同（它们本就是
不同的极端补全），但每条序列内部的对比是配对的。

## 反转示例

容量为 2，日志 `[1, 1, 2, 3, Gap(1, allowed={1, 2})]`，只有两种补全：

| 缺失请求 | 完整序列 | LRU 回源 | LFU 回源 | d | 结论 |
| --- | --- | --- | --- | --- | --- |
| `1` | `(1,1,2,3,1)` | 4 | 3 | +1 | LFU 省 1 次 |
| `2` | `(1,1,2,3,2)` | 3 | 4 | -1 | LFU 反多 1 次 |

共同前缀让两缓存都持有 `{2, 3}`：补 `1` 时 LFU 因保留高频键 `1`
而命中、LRU 未命中；补 `2` 时 LRU 命中而 LFU 已淘汰 `2` 未命中。
同一份抽样日志因此能得出两种相反结论，运行演示可见逐步回放。

## 运行

```bash
python -m analysis.demo
python -m pytest tests/test_reach_analysis.py -q
```

## 规模与复杂度

设不同分区数为 N、缓存容量为 C、缺失段总长为 G。联合状态数受
LRU/LFU 各自可达缓存状态组合上界约束（小样本下很小），每步按允许
集合大小分支，复杂度约为 `O(状态数 × (观测长度 + G × |allowed|))`。
补全总数可由 `AccessLog.completion_count()` 预判；过大时 DP 仍按
状态去重，而暴力枚举只适合小样本校验。
